## 2026-08-16 — старт TDD-режима

**Контекст:** пользователь считает проект в ступоре — автомонтаж и работа
с кадрами не работают до конца корректно, на выходе сырые ролики. Решено:
инкрементальный TDD поверх текущей архитектуры (не переписывать с нуля),
разработка/тесты — на Windows-машине (логика), реальный e2e-прогон
(ffmpeg/LM Studio/Whisper — весь стек Mac-специфичен) — на Mac пользователя.

**Сделано:**
- Прогнан весь набор (127 тестов) на Windows впервые — ~50 падений/ошибок,
  из них 4 реальных бага (не связаны с отсутствием ffmpeg):
  1. `cli.py --help` падал `UnicodeEncodeError` на Windows-консоли (cp1251)
     из-за кириллицы/стрелок в тексте — теперь stdout/stderr принудительно
     UTF-8.
  2. `core/worker_lock._pid_alive()` был сломан на Windows: `os.kill(pid, 0)`
     там не бросает исключение для мёртвого pid → мёртвый lock никогда не
     перехватывался. Переписано через WinAPI (`OpenProcess`+
     `GetExitCodeProcess`), POSIX-путь (Mac/Linux) не тронут.
  3. `httpx` не был явной зависимостью (тесты мокают его напрямую).
  4. Тест `~` expansion был завязан на `HOME`, который Windows игнорирует
     (там `USERPROFILE`).
- Остальные ~46 падений — честные: тестам, зависящим от ffmpeg-фикстур,
  добавлен skip с причиной, когда `ffmpeg`/`ffprobe` не в PATH, вместо
  каскада `FileNotFoundError`. Сама архитектура этих тестов (синтетическое
  видео через ffmpeg lavfi, реальный пиксельный анализ) хорошая — не
  переделывать на моки, просто честно пропускать без бинарников.
- Итог: **0 failed / 0 error** на этой машине (без ffmpeg).
- Заведён `TEST_BACKLOG.md` — приоритизированный список пробелов в
  покрытии, привязанный к ТЗ §23 и жалобе «сырые ролики». Пункты с
  пометкой **[MAC]** нельзя закрыть полностью без реального прогона.
- Коммит: `1af6bfa` — «Фикс кросс-платформенных багов + честные skip
  вместо каскада FileNotFoundError».
