Да, моя ошибка. Результат ниже.

## 1. Краткое резюме продукта

Это сервис, который из сырых видео и музыки автоматически собирает готовый ролик: выбирает лучшие фрагменты, удаляет брак, синхронизирует монтаж с битами музыки, применяет стиль, формат, длительность и дает пользователю возможность вручную поправить выбор перед финальным рендером.

Текущий проект уже не с нуля: есть Streamlit, FFmpeg, OpenCV, PySceneDetect, librosa, MediaPipe, SQLite, пресеты, ручная разметка, анализ качества, дедупликация, музыкальная синхронизация и A/B/C/D варианты.

Важно: файл, который реально загружен в окружение, относится к MVP дрона для отбора CO2, а не к Auto Video Editor. Поэтому ниже я опираюсь на текстовое описание проекта из сообщения. 

## 2. Главная проблема текущей версии

Сейчас это рабочий локальный прототип, но не масштабируемый продукт.

Главные ограничения:

1. `gui.py` на 4500 строк смешивает UI, бизнес-логику и пайплайн.
2. SQLite без миграций опасен для развития.
3. Абсолютные пути ломают переносимость проектов.
4. Пресеты есть, но веса и логика частично зашиты в код.
5. Рейтинг рендера собирается, но не влияет на алгоритмы.
6. Автоматический монтаж работает, но качество выбора кадров пока основано на эвристиках, а не на обучении на данных.

## 3. Целевая концепция

Продукт должен стать не просто “рендерилкой”, а системой планирования монтажа.

Правильная логика:

1. Сначала анализ материала.
2. Потом создание библиотеки фрагментов.
3. Потом пользовательский контроль.
4. Потом выбор стиля.
5. Потом выбор формата.
6. Потом выбор длительности.
7. Потом генерация timeline.
8. Потом preview.
9. Потом финальный render.

Стиль не должен включать формат и длительность. Стиль отвечает за монтажную эстетику. Формат отвечает за aspect ratio, resolution, crop. Длительность отвечает за плотность отбора.

## 4. Рекомендуемая архитектура

### MVP локальный

* UI: Streamlit или Gradio
* Backend core: Python
* Video processing: FFmpeg, OpenCV
* Scene detection: PySceneDetect
* Audio: librosa, Essentia
* CV: MediaPipe, YOLO, CLIP optional
* Storage: SQLite
* Config: YAML presets
* Render: FFmpeg CLI через безопасный subprocess list args
* Jobs: локальная очередь задач

### Коммерческая версия

* Frontend: Next.js
* Backend API: FastAPI
* Queue: Celery или RQ
* Broker: Redis
* DB: PostgreSQL
* Storage: S3-compatible
* Workers: CPU workers и GPU workers
* Render service: FFmpeg workers
* ML service: отдельный сервис анализа
* Auth: Clerk, Auth0 или собственная JWT схема
* Billing: Stripe
* Deployment: Docker Compose для MVP, Kubernetes позже

## 6. Что взять в MVP 1

Не надо сразу делать “идеальный AI-монтажер”.

В MVP 1 должно быть:

1. Загрузка нескольких видео.
2. Загрузка музыки.
3. Автоанализ видео.
4. Список найденных сцен.
5. Оценка качества сцены.
6. Причина выбора или отклонения.
7. Pin / Exclude / Required / Forbidden.
8. Выбор стиля.
9. Выбор формата отдельно.
10. Выбор длительности отдельно.
11. Beat-sync по музыке.
12. Preview render.
13. Финальный render.
14. История проектов.
15. 5-6 реально отличающихся стилей, не 20.

## 8. Форматы отдельно от стилей

| Формат             | Aspect ratio | Типичная длительность |
| ------------------ | -----------: | --------------------: |
| YouTube Shorts     |         9:16 |             15-60 сек |
| Instagram Reels    |         9:16 |             15-90 сек |
| TikTok             |         9:16 |             10-60 сек |
| YouTube Horizontal |         16:9 |              1-10 мин |
| Full HD Horizontal |         16:9 |                 любая |
| 4K Horizontal      |         16:9 |                 любая |
| Square             |          1:1 |             15-60 сек |
| Wide Cinematic     |         21:9 |       30 сек и больше |
| Custom             |        любой |                 любая |

Для vertical crop нужно использовать face/person/object tracking. Если людей нет, брать saliency + motion center. Если crop плохой, показывать пользователю предупреждение.

## 9. Алгоритмы для MVP

Обязательно:

* PySceneDetect для сцен.
* OpenCV sharpness через Laplacian variance.
* Brightness/contrast через histogram metrics.
* Shake detection через optical flow или feature tracking.
* pHash для дублей.
* MediaPipe Face/Person для людей.
* librosa для BPM, onset, beats, RMS energy.
* FFmpeg для render, normalize, crop, scale.
* YAML presets для стилей.

Позже:

* CLIP embeddings.
* Video embeddings.
* Aesthetic model.
* YOLO object detection.
* Smart reframing на базе tracking.
* Learning from user ratings.
* Reference-based editing “сделай как в примере”.

## 10. Конкуренты

Рынок уже есть, но ниша остается.

* GoPro Quik автоматически выбирает лучшие моменты, синхронизирует с музыкой и добавляет переходы. Это близкий конкурент для action/drone/travel. ([Google Play][1])
* OnBeat делает beat-sync для Reels и travel recap, но больше похож на mobile app с шаблонами. ([App Store][2])
* VEED и Kapwing больше ориентированы на talking video, podcast, social clips и transcript-based editing. ([VEED][3])
* Magisto позиционируется как fully automated AI engine для готовых video stories. ([Vimeo][4])
* Adobe уже двигается в сторону AI first draft editing, где AI собирает черновой монтаж из клипов, но оставляет контроль пользователю. ([The Verge][5])
* Apple/Final Cut Pro также идет к AI Montage Maker, beat detection, visual search и auto crop. ([Digital Camera World][6])

Ниша продукта: не “еще один AI video editor”, а специализированный auto-montage engine для travel, drone, family, event, cafe promo, nature и lifestyle видео, где пользователь загружает много сырого материала и хочет получить красивый ролик без ручной нарезки.

## 14. Команда

Минимально:

* 1 strong Python/video engineer
* 1 fullstack developer
* 1 UX/UI designer part-time
* 1 ML/CV engineer part-time

На раннем MVP один сильный fullstack/Python developer может сделать многое, если не лезть глубоко в ML.

Очень сложные блоки:

* smart crop
* хороший aesthetic scoring
* стабильный cloud render
* обучение на пользовательских рейтингах
* качественная музыкальная структура intro/drop/chorus

## 15. С чего начать прямо сейчас

1. Разобрать `gui.py` на слои.
2. Ввести нормальную модель Project.
3. Добавить миграции БД.
4. Перевести пути на относительные.
5. Вынести веса scoring в YAML.
6. Сделать экран найденных сцен нормальным продуктовым экраном.
7. Оставить 6 стилей и довести их до качества.
8. Сделать preview render быстрым и обязательным.
9. Добавить explainability: почему фрагмент выбран.
10. Добавить warning до рендера, если материала не хватает.
