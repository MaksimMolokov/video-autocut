# Продуктовая проблема и новый пользовательский сценарий

## 1. Основная проблема

**Скрытое допущение текущей системы:** входящий материал уже достаточно хороший.

Система умеет выбирать лучшее из того, что дано — но она не умеет вытаскивать
хорошее из плохого.

### Что происходит сейчас

Реальный пользователь загружает папку с 40 видео:
- часть снята в автомобиле на ходу (тряска, плохое освещение)
- часть тёмные или пересвеченные
- часть — случайные обрезки и технический брак
- часть — три почти одинаковых дубля одной сцены
- и только несколько действительно хороших кадров

Из этого массива система берёт все `good_ranges`, которые проходят
пороги резкости/яркости по пресету — и строит монтаж.

**Результат:** сырой, с повторами, без логики, непредсказуемого качества.

### Разрыв ожиданий

| Что думает пользователь | Что делает система |
|---|---|
| "Система сделает красиво" | "Дайте мне красивые исходники" |
| "Я просто загружу видео" | Нужен подготовленный материал |
| "Разные варианты будут разными" | Берёт лучшее из одного и того же пула |

Закрыть этот разрыв — главная продуктовая задача следующего этапа.

## 2. Новый пользовательский сценарий

### Текущий (проблемный) путь

```
Загрузка видео
      ↓
Выбор стиля (работает со всем подряд)
      ↓
Выбор музыки
      ↓
Рендер → непредсказуемый результат
```

### Предлагаемый (правильный) путь

```
Загрузка видео
      ↓
[Автоанализ — 30–120 с]
  - разбивка на сцены
  - оценка технического качества
  - поиск лиц, объектов, типов плана
  - отсев брака и дублей
      ↓
Просмотр найденных фрагментов (опционально)
  - карточки с превью, оценкой, тегами
  - пользователь может одобрить / отключить / поставить приоритет
      ↓
Выбор стиля
  - стиль получает уже отфильтрованные кандидаты
  - разные стили используют одну библиотеку с разными весами скоринга
      ↓
Выбор музыки → синхронизация
      ↓
Рендер → сравнение вариантов
      ↓
Экспорт
```

### Ключевое изменение

**Стиль работает не с папкой видео, а с библиотекой одобренных моментов.**

Это позволяет:
- одинаково хорошо работать на плохих и хороших исходниках
- не анализировать видео заново при смене стиля или музыки
- давать пользователю видимость и контроль над тем, из чего собирается монтаж

---

## 3. Три режима работы

### Режим «Авто»
Система выбирает всё сама. Пользователь нажимает «Анализировать» и сразу идёт
к выбору стиля. Подходит для пользователей, которые хотят минимум действий.

### Режим «Ревью»
Система предлагает найденные фрагменты, пользователь просматривает и может
одобрить или отключить любой из них. Подходит для тех, кто хочет контролировать
материал, но не хочет вручную разбирать видео.

### Режим «Ручной»
Пользователь сам отбирает фрагменты из найденных системой. Подходит для
профессиональных пользователей, которые знают, чего хотят.

---

## 4. Связь предобработки со стилями монтажа

Одна и та же библиотека фрагментов — разные веса скоринга при выборе.

| Стиль | Приоритет при выборе кандидатов |
|---|---|
| F1 (Rapid F1) | Высокий action_score, motion_score |
| F2 (Cinematic) | Высокий cinematic_score: stability + sharpness + camera motion |
| F3 (Urban Pulse) | Высокий social_score: motion + faces + scene variety |
| F4 (Sport) | Максимальный action_score + motion_score |
| F5 (Premium) | Максимальный quality_score + stability + sharpness |
| F6 (Travel) | Высокий aesthetic + color + uniqueness |

Технически: `ClipSelectionStrategy.get_feature_weights()` уже это делает.
После добавления предобработки — та же логика, но с более качественным пулом кандидатов.
