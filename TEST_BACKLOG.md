# Test Backlog — TDD-план развития

Рабочий бэклог для скилла `video-autocut-dev` (запускается по выходным).
Каждый пункт закрывается циклом **тест → фикс/фича → зелёный прогон → коммит**.
Формат пункта: `[ ]`/`[x]`, модуль, что проверяем, зачем (какому пункту
ТЗ §23 «Критерии качества» или жалобе пользователя это отвечает).

Источники: [TZ_AUTO_VIDEO_EDITOR_V2.md](TZ_AUTO_VIDEO_EDITOR_V2.md) §23,
[DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md), устный фидбек 2026-08-16:
«на выходе очень сырые ролики» — до конца некорректно работает ни
автомонтаж, ни работа с кадрами.

## Правила работы с бэклогом
1. Каждый прогон скилла берёт **1–3 пункта сверху**, не больше — небольшие
   зелёные коммиты, не одна гигантская правка.
2. Готовый пункт помечается `[x]` с датой и номером коммита.
3. Если по ходу работы находится новый пробел в покрытии — дописать пункт
   вниз соответствующего раздела, а не молча пропустить.
4. Пункты, помеченные **[MAC]**, нельзя полноценно проверить на Windows без
   ffmpeg/LM Studio — юнит-логика тестируется здесь, а факт «стало ли видео
   на выходе менее сырым» подтверждает пользователь на реальных исходниках.
5. Раз в несколько прогонов — сверять этот список заново с ТЗ §23 и с кодом
   (`grep -n "^def "` по core/*.py), не разросся ли необследованный код.
