# Техническое задание: Auto Video Editor V2

> Сохранено 2026-07-01. Источник: заказчик (Максим). Базовая LLM-спецификация: [SPEC_LOCAL_VIDEO_ANALYSIS.md](SPEC_LOCAL_VIDEO_ANALYSIS.md) — анализ сцен строится на **Qwen3-VL 8B Instruct (MLX 4bit) через LM Studio API**.

Главная идея: сначала система создает понятную базу сцен из всех исходников, потом подбирает сцены под сценарий, потом собирает черновик, потом дает пользователю визуально заменить неудачные куски.

## 1. Цель проекта

Разработать локальное приложение для полуавтоматического монтажа видео, которое позволяет пользователю указать исходные видеофайлы, музыкальный файл, сценарий или готовый пресет, а затем автоматически собрать черновой видеоролик с возможностью ручной проверки и замены фрагментов.

Продукт не должен быть полноценным видеоредактором уровня Premiere Pro. Главная задача: быстро собрать качественный черновик ролика из лучших сцен, подходящих под сценарий, музыку, формат и заданную длительность.

## 2. Основная проблема текущей версии

Текущая версия пытается сразу перейти к монтажу, но недостаточно корректно понимает содержимое исходных видео. Из-за этого монтаж получается нестабильным, фрагменты могут повторяться, сцены могут плохо подходить к идее ролика, а пользователь не видит прозрачной логики, почему система выбрала именно эти куски.

Новая версия должна сначала выполнять полноценный анализ исходников, формировать каталог найденных сцен, показывать эти сцены пользователю, а уже потом собирать черновой монтаж.

## 3. Основная пользовательская логика

Пользовательский путь:

1. Создание проекта.
2. Выбор локальных видеофайлов или папки с видео.
3. Выбор музыкального файла.
4. Выбор сценария или готового пресета.
5. Выбор формата ролика: вертикальный, горизонтальный, квадратный.
6. Выбор итоговой длительности: например 15, 30, 45, 60 секунд.
7. Запуск анализа.
8. Просмотр найденных сцен и рекомендованных фрагментов.
9. Генерация черновика.
10. Просмотр черновика.
11. Просмотр таймлайна черновика.
12. Замена неудачных фрагментов на альтернативные.
13. Повторная генерация.
14. Финальный экспорт в mp4.

## 4. Входные данные проекта

1. Один или несколько локальных видеофайлов.
2. Локальная папка с видеофайлами.
3. Один музыкальный файл.
4. Текстовый сценарий от пользователя.
5. Готовый сценарный пресет.
6. Настройки итогового ролика: формат кадра, длительность, стиль монтажа, динамичность, наличие вступления, наличие финального кадра, необходимость синхронизации с музыкой.

## 5. Сценарий и пресеты

Пользователь не обязан каждый раз писать сценарий вручную. В системе должны быть готовые пресеты.

Примеры пресетов:

1. FPV обзор локации.
2. Реклама ресторана или кафе.
3. Реклама коворкинга.
4. Туристический ролик.
5. Семейное видео.
6. День рождения.
7. Дроновое cinematic video.
8. Быстрый Reels для Instagram.
9. Вертикальный TikTok клип.
10. Презентация недвижимости.
11. Атмосферный slow cinematic.
12. Динамичный action монтаж.

Каждый пресет должен содержать: описание идеи ролика, рекомендуемую структуру, типы сцен для поиска, желательную динамику, правила вступления, правила финала, допустимую длительность фрагментов, правила синхронизации с музыкой.

## 6. Структура сценария

Сценарий описывает структуру будущего ролика:

1. Вступление: общий красивый кадр или вход в локацию.
2. Развитие: основные зоны, объекты, движение, детали.
3. Кульминация: самый сильный, красивый или динамичный фрагмент.
4. Финал: понятный завершающий кадр, логотип, общий вид или спокойный фрагмент.

Хороший ролик не может быть случайной нарезкой: у него есть начало, середина и завершение.

## 7. Анализ видео

1. Технический анализ: длительность, FPS, разрешение, ориентация, битрейт, наличие аудио, стабильность файла.
2. Разбиение на сцены: смены сцен, длинные непрерывные фрагменты, исключение коротких/плохих участков.
3. Оценка качества кадра: резкость, размытие, пересвет, тёмные кадры, тряска, шум, читаемость.
4. Анализ движения: плавное движение, резкое движение, статика, приближение, отдаление, пролёт, поворот.
5. Смысловой анализ: что в кадре — люди, здания, еда, интерьер, экстерьер, природа, транспорт, крупные/общие планы.
6. Превью: миниатюра, короткий preview clip, начальный/конечный таймкод, источник.

## 8. Роль локальной LLM

LLM не работает с сырым видеофайлом напрямую:

1. Система анализирует видео через OpenCV, FFmpeg, PySceneDetect (и опционально MediaPipe, CLIP, Whisper).
2. Для каждого фрагмента создаётся карточка сцены.
3. В карточке: описание, теги, оценки качества, таймкоды, preview.
4. LLM получает структурированное описание сцен, а не видеофайл.
5. LLM сравнивает сценарий с карточками сцен.
6. LLM помогает выбрать фрагменты для вступления, середины, кульминации и финала.

LLM — сценарный помощник и ранжировщик, а не единственный механизм анализа.

**Уточнение реализации (из SPEC_LOCAL_VIDEO_ANALYSIS.md):** визуальные описания кадров сцен формирует Qwen3-VL 8B (vision) через LM Studio API (`localhost:1234/v1`, structured output). Она же используется как ранжировщик сцен под сценарий.

## 9. Карточка найденной сцены

Поля сцены:

1. id сцены
2. id исходного видео
3. путь к исходному видео
4. начало фрагмента
5. конец фрагмента
6. длительность
7. preview файл
8. thumbnail
9. описание сцены
10. теги
11. оценка качества
12. оценка красоты
13. оценка стабильности
14. оценка соответствия сценарию
15. тип сцены
16. рекомендуемое место в ролике
17. причина рекомендации

Типы сцен: intro, establishing shot, detail shot, action shot, people shot, location shot, food shot, product shot, transition shot, climax shot, ending shot.

## 10. Каталог сцен

Экран со всеми найденными сценами: thumbnail, длительность, источник, таймкоды, рейтинг качества, рейтинг соответствия сценарию, теги, кнопка воспроизведения, статус использования в черновике, детальный просмотр. Реальные визуальные превью, а не иконки.

## 11. Генерация черновика

Вход: список сцен, сценарий, музыкальный анализ, формат, длительность, стиль, динамика.

Монтажный план содержит: порядок сцен, таймкоды входа/выхода, длительность фрагмента в ролике, источник, причину выбора, рекомендуемый crop, место в структуре, связь с музыкальным битом.

## 12. Структура черновика

Драматургия: вступление → основная часть → развитие → сильный момент → финал.

Пример для 30 секунд: 0–4 вступление; 4–12 раскрытие; 12–22 сильные сцены; 22–27 кульминация; 27–30 финал.

Не начинать со случайной середины действия; не заканчивать случайным обрывом.

## 13. Таймлайн черновика

Показывает: общую длительность, все фрагменты, длительность каждого, источник, thumbnail, место в сценарии, причину выбора, статус синхронизации с музыкой. Визуально, а не только текстом.

## 14. Замена фрагментов

1. Пользователь выбирает фрагмент на таймлайне.
2. Система показывает альтернативы, подходящие под то же место сценария.
3. Каждую альтернативу можно воспроизвести.
4. Пользователь выбирает замену → план обновляется → повторная генерация.

Система хранит и неиспользованные подходящие сцены.

## 15. Просмотр фрагментов

Для каждой сцены: открыть preview, проиграть, исходный таймкод, описание, причина рекомендации, где используется, пометить хорошей/плохой, запретить использование, закрепить для обязательного использования.

## 16. Работа с музыкой

Определять: длительность, темп, биты, сильные доли, энергетические/спокойные/кульминационные участки, точки для смены кадров.

Музыка учитывается, но не является единственным фактором: спокойное вступление сценария важнее случайного бита.

## 17. Форматы экспорта

9:16, 16:9, 1:1. Автокадрирование с сохранением важных объектов, без обрезки лиц, безопасная центральная область, preview перед экспортом.

## 18. Рендеринг

1. Быстрый preview render (низкое разрешение).
2. Финальный export render (качественный mp4).

## 19. Хранение данных проекта

Локально: настройки, исходники, результаты анализа видео и музыки, карточки сцен, монтажный план, история замен, пути к черновику и экспорту. SQLite + папка проекта для preview/thumbnails/render/cache.

## 22. Что не входит в MVP

Полноценный ручной редактор, сложные эффекты, многослойная графика, титры уровня AE, облачный рендеринг, командная работа, сложная цветокоррекция, генерация новых кадров, автосоздание полного сценария без участия пользователя.

## 23. Критерии качества

1. пользователь понимает, какие сцены найдены;
2. пользователь видит реальные preview;
3. черновик не собирается из случайных кусков;
4. начало выглядит как вступление;
5. финал не выглядит обрывом;
6. нет беспричинных повторов фрагментов;
7. каждый фрагмент можно заменить;
8. альтернативы похожи по смыслу;
9. после замены можно пересобрать;
10. стабильный экспорт в mp4.

## 24. Главный принцип разработки

Сначала — надёжная внутренняя карта видео, а не интерфейс и эффекты.

Три главные сущности: **Проект. Сцена. Монтажный план.** Всё остальное — вокруг них.

Порядок переработки:

1. Убрать идею «сразу монтировать после загрузки».
2. Стабильный анализ исходников и каталог сцен.
3. Экран найденных сцен с реальными превью.
4. Генератор монтажного плана.
5. Preview render.
6. Таймлайн и замена фрагментов.
7. Потом — пресеты, LLM-подбор, сценарная логика.

Монтажный план — отдельная сущность: какие куски, откуда, в каком порядке, почему выбраны, сколько секунд занимают.
